## 叶页重建与删除语义

涉及 [leaf_node.rs](../src/nodes/leaf_node.rs) 和 [叶节点测试](../src/tests/leaf_node.rs)。

整理、升级 mini page、复制分裂右页时，源记录已经按键排序且没有重复键。原实现仍逐条调用普通 `insert`，重复执行二分搜索；升级及分裂还为每条记录分配完整键。现在将新记录写入提取为共享的 `insert_new_at`，重建路径使用 `append_sorted` 追加到元数据尾部。长度和空间检查仍然执行，debug 构建还检查追加顺序。在 release 构建中，这移除了重建的逐条搜索和无效元数据搬移；记录处理为线性遍历，另加实际键值字节的复制成本。

复制无公共前缀的页面时，直接借用源键；存在压缩前缀时，使用可复用的 `Vec` 拼接完整键，避免每条记录都重新分配。`Vec::clear` 保留容量，因此同一缓冲区可以跨记录复用，遇到更长键时仍可能扩容。[Rust `Vec::clear` 文档](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.clear)

`get_kv_num_below_key` 改为复用现有二分 `lower_bound`，减去 fence 元数据数量；保持“严格小于分裂键”的定义。现有生成式模型测试补充对此计数的校验。

另一个实现缺陷出现在 `consolidate_inner`：旧逻辑只识别 `Delete`，把表示已删除缓存记录的 `Phantom` 当作普通记录转成 `Insert` 或 `Cache`。这会重新暴露旧值；空值场景还可能触发 debug 断言。现在通过 `is_absent()` 同时识别两类删除标记：要求清理时一起移除，要求保留时维持删除语义。回归覆盖带旧值、空值和正常保留记录。此问题是内部重建操作的语义缺陷，本报告不把它扩大为所有生产调用路径都可触发的故障。

## 范围扫描

涉及 [range_scan.rs](../src/range_scan.rs) 和 [tree.rs](../src/tree.rs)。

可变扫描在根节点仍为叶页、并触发扫描缓存提升时，会继续调用需要父节点的路径，随后对 `None` 执行 `unwrap`。根叶页本来就不对应 mini page；现在和只读扫描、普通读取一致，直接扫描根页。回归将提升概率设为 100%，覆盖空树、单记录树及重复结束调用。

`scan_mut_with_count`、`scan_mut_with_end_key` 在获取叶页前拒绝空键；后者同时拒绝起始键大于结束键，使输入规则与只读扫描一致。两个扫描器在 `scan_cnt == 0` 时立即结束，不再因设置了结束键而重复访问页面和比较边界。

## WAL 截断恢复与空闲 I/O

涉及 [wal/mod.rs](../src/wal/mod.rs)。

原 WAL 读取为最后一个不足整段的数据块创建完整段长的零填充缓冲区，解析器可能把文件中缺失的记录尾部当作真实的零字节。即使首次读取拒绝了残缺记录，恢复后在下一段继续写入时，文件扩展形成的零填充间隙也可能让残缺记录重新表现为完整记录。

现在最后一段缓冲区只覆盖文件实际存在的字节；恢复扫描同时返回最后一条完整记录的 LSN 和有效结束偏移，继续追加前截去无效尾部。下一条 LSN 仍从完整记录推导，段对齐追加策略保持不变。`File::set_len` 的截断及扩展语义是这里需要显式处理尾部的依据。[Rust `File::set_len` 文档](https://doc.rust-lang.org/std/fs/struct.File.html#method.set_len)

空闲 WAL 的另一个问题是：已经刷盘的非空缓冲区在后续 `flush` 时仍重复写扇区并同步文件。现在只有 `buffer_cursor` 超过 `flushed_cursor` 才写入并更新持久化 LSN；显式换段仍然执行。记录型 VFS 回归验证写入次数、刷盘次数、跨扇区增量写及清洁段换段行为。该证据验证调用行为，不能替代真实设备上的吞吐和持久性测试。

截断回归枚举记录头、负载及段边界的各个截断位置，并在恢复追加后再次读取，检查缺失记录不会被补零“复活”。本轮不增加校验和，也不承诺识别内容长度合法但字节已损坏的记录。

## 配置与快照恢复

涉及 [config.rs](../src/config.rs)、[error.rs](../src/error.rs) 和 [snapshot.rs](../src/snapshot.rs)。

配置 setter 和校验曾在拒绝非法输入前进行乘加减运算，极值会导致 debug 溢出 panic，或在 release 中回绕。现在键长度派生使用饱和乘法，记录与页容量计算使用有界、检查式运算；同时拒绝零页大小、无法构造分配布局的缓存容量、非有限或超出 `[0, 1]` 的访问复制比例，以及不能推进到下一个版本的快照版本。分配布局限制按标准库契约校验。[Rust `Layout::from_size_align` 文档](https://doc.rust-lang.org/std/alloc/struct.Layout.html#method.from_size_align)

快照头原先直接把 Rust 结构体转为字节切片写出，包含未初始化 padding 的风险；恢复时则在校验前直接构造结构体，非法 `bool` 位模式本身就不合法。现在写入时先创建零初始化缓冲区，再按既有字段偏移写入；读取时先验证长度和布尔字节，再构造元数据，并检查 magic、文件长度、映射表范围与长度、mini page 映射数量、根信息和版本边界。Rust 对 `bool` 值、未初始化数据及数据竞争的约束适用于 `unsafe` 代码。[Rust Reference：未定义行为](https://doc.rust-lang.org/reference/behavior-considered-undefined.html)

恢复使用快照中的配置时，先校验配置，再计算分配尺寸类别和创建快照管理器；头部 I/O 错误、无效头和容量不足通过现有 `Result` 路径返回错误。WAL 延后到恢复成功前创建，避免输入无效或缓存不足时提前创建日志文件及后台写入线程。

恢复过程中可能已经分配内部节点和部分 mini page，随后才发现缓存不足。新增两个 RAII 所有者跟踪这些分配；提前返回或栈展开时分别释放内部节点、通过循环缓冲区分配元数据回收 mini page，成功交给 `BfTree` 后解除临时所有权。恢复中的树还含有磁盘 ID，不能假定可以按完整树遍历销毁。这里依赖正常作用域结束和展开时的析构，不覆盖进程中止或 `panic=abort`。[Rust `Drop` 文档](https://doc.rust-lang.org/std/ops/trait.Drop.html)

磁盘及 cache-only 快照测试原先复用固定的 `target/test_simple` 路径，独立测试进程并行运行时可能互相删除文件。现在每次测试使用独立临时目录，使 debug、release 等独立运行互不干扰；这项修改属于测试隔离，不改变快照运行协议。

## 定位 I/O 的中断重试

涉及 [fs/mod.rs](../src/fs/mod.rs) 和 [std_direct_vfs.rs](../src/fs/std_direct_vfs.rs)。定位读写对 `ErrorKind::Interrupted` 重试，重试封装将其他错误交还调用方；完整读写辅助函数保留短读写循环，直接 I/O 仍保留完整传输断言。回归覆盖连续中断、不可重试错误、非零偏移、覆盖写、EOF 与空缓冲区。重试中断符合标准库完整读取的语义。[Rust `Read::read_exact` 文档](https://doc.rust-lang.org/std/io/trait.Read.html#method.read_exact)

## 兼容性与未解决事项

- 正常树操作和节点格式保持一致。配置检查收紧，曾经通过校验但不能安全构建的配置现在返回错误。
- `ConfigError` 增加 `CopyOnAccessRatio` 和 `SnapshotVersion` 变体。下游若对这个公开枚举做无通配分支的穷举 `match`，需要补充分支；不能把这项变化描述为完全无源码兼容影响。
- 快照仍使用现有本机字段布局、`usize` 宽度及字节序。本轮修复 padding 初始化和输入检查，没有把格式改成跨架构、跨布局的可移植协议。
- 快照恢复只增加了头部及部分布局检查。映射记录、节点负载、子节点图等尚未完成全面校验，损坏输入仍可能触发断言或其他问题；不能据此宣称支持任意不可信快照。
- 叶页原 `data: [u8; 0]` 的借用边界问题已在后续修复中改为携带实际页长的 DST；同工具、默认别名检查下原用例及确定性叶页测试通过。具体实现与性能复核见 [叶页边界修复](leaf-safety-2026-09-27.md)。
- 内部节点的乐观读仍可能让普通字段读取与写入重叠。读取后的版本校验不能消除已经发生的数据竞争；本轮未重写该并发协议。
- 真实磁盘故障、持久性、并发扩展和尾延迟需要各自的负载与故障测试。节点微基准只说明对应重建操作，不证明整个引擎或所有工作负载都更快。
